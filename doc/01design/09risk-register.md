## 10.1 阻塞项（2026-07-31：已全部解除）

v0.2 时登记的三项阻塞已全部确认，**当前无阻塞项**：

| 原阻塞项 | 结论 | 详见 |
|---|---|---|
| **数据合规** | 不含敏感数据、不受等保约束、允许送公有云 LLM | [总体架构的合规约束](./01architecture.md) |
| **出网通路** | 内网可访问 `api.deepseek.com`，worker 直连，无需代理审批 | [总体架构的用户范围](./01architecture.md) |
| **内网服务器配置** | 32 核 / 64 GB / 磁盘充裕 | [运维设计的部署拓扑与容量输入](./08operation-design.md) |

**由此解除的下游依赖**：[ADR-0009](./adr/0009-default-model-selection.md) 从「待确认」转为「已接受」；§7.4 的脱敏与加密要求整体撤销；§8.1 的容量数字从假设变为实算。

> **部署时仍需复验一次**：出网结论应在实际部署的那台服务器上用 `curl https://api.deepseek.com` 复验，而不是依赖「内网应该能通」的一般判断 —— 出网策略常按网段或主机粒度配置。成本几秒钟。

沙箱的网络策略与此**无关且不变**：沙箱保持零出网，模型调用发生在 worker 侧，不经过沙箱（§7.3.4）。

## 10.2 风险登记

| 风险 | 影响 | 应对 |
|---|---|---|
| **Postgres 单点** | 故障即全局不可用，且已中断的任务无法恢复 | §8.5 备份。[总体架构的质量属性](./01architecture.md) 已决不设 SLA，**无法再用指标论证是否上主从**，改按故障代价判断（§8.2） |
| **P0 效果不达预期** | agent 写不出有用的分析代码，则后续所有工程投入作废 | 正是 P0 先于 P1 的原因（[实施计划基线](../03plan/CLAUDE.md)） |
| ~~磁盘配额缺口~~ | **已关闭**（2026-07-31）。`/workspace` 5GB XFS project quota + `/tmp` tmpfs 512MB | §7.3.5，P1 落地 |
| **workspace 本地副本无界增长** | 配额是 per-thread 的，而 workspace 在容器销毁后仍留在宿主机。总量 = 历史 thread 数 × 5GB，worst case 是 TB 级 | **归档回收已于 P4 定案不做**（§6.5.1：实测 ~350KB/会话、2.5 GB/年，收益与复杂度严重不匹配），**仍无期次**。这一条因此**靠的是实测量级而不是机制** —— 监控（`workspace-report.sh` + §8.3 告警）与 §6.5 的重估触发条件是它现在唯一的兜底 |
| **XFS 挂载成了硬启动依赖**（2026-08-10，P4） | 配额改 fail-closed 之后，`data/sandbox` 的 prjquota 挂载不在时 broker 拒绝建会话，**平台整体不可用**（`POST /threads` 一律 500）。用 loop 设备造的挂载重启后不会自动挂回来，实测已因此宕过一次 | **这是设计的正确行为**（此前是静默无配额，等于威胁表「写满磁盘」那一格敞着），代价明确接受。缓解靠 §8.5 的重启仪式 + §8.3 的「有进程抓不到了」告警。生产上用真实分区而非 loop 设备可消除这条 |
| **单人开发，架构决策无人复核** | 错误决策可能拖到实现阶段才暴露，返工成本高 | [ADR 索引](./adr/README.md) 的 ADR 是唯一的自我审查手段，决策变更须同步更新（[总体架构的开发约束](./01architecture.md)） |
| **会话凭据明文传输** | 走 HTTP（[运维设计的部署拓扑与容量输入](./08operation-design.md)），Session Cookie 无 `Secure` 标志，同网段抓包可窃取会话 | 已按 §7.1 威胁模型接受。触发重估的条件见 [运维设计的部署拓扑与容量输入](./08operation-design.md) |
| **用户范围被悄悄放开到全院学生** | 基数增一个数量级，[总体架构的架构原则](./01architecture.md) 权衡、§8.1 容量、ADR-0001 单机结论同时失效 | [总体架构的用户范围](./01architecture.md) 已明确边界为「课题组研究生」。放开前必须重审这三处，不能当作纯运营决定 |
| **写操作重复执行** | ~~HITL 每次审批恢复都会整节点重跑~~ **（2026-08-02 实测改正：HITL 不致工具重复执行，[总体架构的架构原则](./01architecture.md)）**。仅余崩溃路径：崩溃在工具执行途中时重复执行 `execute` / `edit_file` / `delete`，造成数据污染或使 LLM 看到虚假错误 | §5.6 幂等键方案。**降级**：不再是 P3 HITL 的前置条件，可与 HITL 解耦排期。§5.4 的 run 级自动重试上限维持 1 次（该理由不受影响） |
| ~~**`tool_call_id` 重放稳定性未经验证**~~ | **已关闭**（2026-08-02）。实测中断前后 `tool_call_id` 完全一致 | — |
| ~~**ADR-0014 的幂等键无落点**~~ | **已关闭**（2026-08-03）。改用 `(thread_id, checkpoint_ns)`，两个条件均实测满足 | — |
| **幂等键与 LangGraph 的任务扇出方式耦合** | `checkpoint_ns` 是框架编排细节，不是本平台的领域概念。若 LangGraph 改变扇出粒度（同一轮多个工具调用合成一个 task），键将不再按调用唯一，去重**静默误判**而不报错 | 升级 langgraph 时须重跑并行场景复验（探针已随 `app/spike/` 删除，取回：`git show 30b0fa6:app/spike/probe5_replay_key_stability.py`）。已写入 [ADR-0014](./adr/0014-tool-idempotency-key.md) 的重估触发条件 |
| **LLM 供应商的 prompt cache 影响成本模型** | 实测 62% 的 input token 是 cache 命中，按总量计费/扣配额会高估约 1.6 倍，且方向性地惩罚长会话 | §6.4 已定口径：分开记 `cache_read` 与未命中。**若换模型供应商需重新测这个比例**，它不是 DeepSeek 独有但比例各不相同 |

| ~~**HITL 的触发范围未定**~~ | **已关闭**（2026-08-08，[P3 计划 §7.2](../03plan/P3-plan.md)）。P3 只全量拦 `delete`，不写 `when` 谓词 —— 它低频高危，全量拦不伤可用性 | 残留：`execute` 的条件拦截仍未定，加之前须先量「一次真实分析里谓词命中几次」，见 §5.3 |
| **LLM 服务商 rate limit** | 并发高峰时集中报错 | 需在 worker 侧做退避重试与降级；尚未设计 |
| ~~**checkpoint 表膨胀**~~ | **已关闭**（2026-08-07，P2）。保留期 180 天，判据是会话最后一次活动 | §6.5 保留期表，cron `python -m store.retention` |

### 10.2.1 P6 决策主动接受的四条风险（2026-08-13）

下面四条**不是被发现的问题，是被选择的代价** —— [P6 决策文档](../03plan/P6-decision.md) 的 68 条定案里，每一条都在选项的代价栏里写明过，仍然被选中。登记在这里是为了它们出事时能查到「当时知道，并且认了」。

| 风险 | 影响 | 为什么仍然接受 | 出事后的第一手段 |
|---|---|---|---|
| **组内共享的 skill 可带可执行脚本，且无人通读**（[D11 + B1](../03plan/P6-decision.md)） | skill 里的 `scripts/*.py` 会被 agent 在**引用者自己的沙箱**里执行。而 B1 定了组内共享**免审**，因此这条路上「上架前通读一遍代码」这道防线不存在 | 沙箱本来就是为跑不可信代码建的（gVisor + 零出网 + 配额），它对同组人写的脚本与对 LLM 生成的代码一视同仁；且威胁模型认定用户是校内实名同事（§7.1）。**组内免审又是 A8「所有人都能提审」之后唯一的减压阀**，堵上它审核队列会被埋掉 | **组内共享的 skill 不允许带可执行脚本**（只收 `.md` / `.txt`），推平台目录时才允许带 `.py`。这条已经想好但没有采纳，留作缺口暴露后的第一手段 |
| **MCP 写操作在崩溃路径下重复执行**（[F8 + F9](../03plan/P6-decision.md)） | 队列是至少一次投递，崩溃恢复会重复调用工具。而定案**既不给 MCP 工具做 HITL 拦截，也不传幂等键** —— 两道都没有。后果与 §10.2 的「写操作重复执行」同类：数据污染，或让 LLM 看到一个首次执行时没有的错误 | **只要接入的 MCP 全是只读检索类，这条路径就不存在**。第一批预计全是检索类 | **声明有写操作的 MCP 一律先不批**（接入规范 §5.4 第 8 项）。要接的前提是 F8 与 F9 一起重定 —— **不是等出问题再查** |
| **教师的数据发到校外**（[F3 + F13](../03plan/P6-decision.md)） | MCP 一律部署在校外，教师上传的财报、论文、企业数据作为工具调用参数发出去。接入规范 §3.6「不自持用户数据」对外网服务**失去执行力** —— 平台既管不了也查不了 | 平台本来就在往校外发数据（DeepSeek API），这是程度问题而非性质问题。**应对是把知情权交回给数据的主人**：上架必须声明，MCP 卡片与配置界面显式标注「此服务位于校外」 | 学院层面若不接受，退路是**只接内网 MCP** —— 那等于回到「平台本地部署」，F3 反转，F10 / F11 跟着重定 |
| **子智能体自带 MCP，绕过外发标注**（[F12 + F13](../03plan/P6-decision.md)） | 你挂的是别人共享的子智能体，它连的是你从没看过的外网服务 —— F13 那条标注是给**主动勾选 MCP 的人**看的，这条路径上看不到 | 共享者把完整能力一起带过来，开箱即用；否则一个「行情分析子智能体」拿不到行情数据，形同虚设 | **缓解已定为必做**：配置界面要展开显示该子智能体会用到哪些 MCP，且外发标注一并展示。**若 P9/P10 落地时漏掉这一条，这条风险就从「已缓解」退回「敞着」** |

## 10.3 技术债与文档缺口

- **智能体设计文档已建**（[`03agent-design.md`](./03agent-design.md)），但**只覆盖了与平台契约耦合的部分**（工具集、文件系统、产物判定、上下文截断）。提示词工程、子 agent 划分、效果评测**仍然空白，刻意推迟到下期** —— 它们只在 worker 进程内部生效，改了不影响别的模块。需要清醒的是：平台的价值完全取决于智能体好不好用（§10.2 风险二），这块债只是被安排了，不是被还了。
  > **2026-08-13：三项里一项排期、两项仍欠。** **子 agent 划分**已由 [P6 决策 G 组](../03plan/P6-decision.md) 定案并排进 P9（一层、最多 5 个、共享沙箱、用主模型）。**提示词工程**（措辞打磨、few-shot、领域知识注入）与**效果评测**仍然空白 —— 后者被 P6 需求方明确排除在范围外。**因此上面那句「平台的价值完全取决于智能体好不好用」这条债，本次一分未还**：P6–P10 做的是「教师能不能自己配」，不是「配出来的效果好不好」。
- ~~**P0 的裸 Docker 沙箱是刻意欠下的债**~~ —— **已偿还**（2026-08-06，P1）。gVisor + §7.3.2 九条加固参数 + `/workspace` 5GB 配额 + `/tmp` 512MB 限容均已落地并经破坏性测试验证；`docker.sock` 已收归 broker。下面这段保留作为背景：**P0 的裸 Docker 沙箱**曾是刻意欠下的债，P1 必须偿还，不可带入上线（[实施计划基线](../03plan/CLAUDE.md)）。P0 探针里的 `docker_sandbox.py`（已随 `app/spike/` 删除，存于 git 历史 `30b0fa6`）是这笔债的实体：无 gVisor、无资源限制、无网络白名单、无磁盘配额，且为省事继承了 `BaseSandbox`（文件操作进容器，与[智能体设计 §4.2](./03agent-design.md) 相反）。**它是验证工具，不是实现起点** —— 正式 backend 要按 [ADR-0016](./adr/0016-sandbox-filesystem-backend.md) 直接实现 `SandboxBackendProtocol`。
- **面向教师的那些契约至今只经 curl 验证过**（2026-08-10）。P3 的审批、配额提示、越权提示，P4 的 `retryable` 重试按钮与 `resumed` 语义，都是照着「将来有前端」设计并验收的，**而它们能不能真的被渲染出来、语义对不对得上，尚无任何证据**。管理员账号管理同样如此：停用离职用户目前要一条 SQL（§6.5.2）。**前端本身的进度与期次不在本文登记**。
- **`quota/policy.py` 的 `ANALYSIS_TOKEN` 仍未校准**（2026-08-10，[P4 §8.14](../03plan/P4-plan.md)）。现值 124,000 是从 2026-08-02 那**一个** P0 探针外推的；五期验收攒下十三个真实样本，区间 **2,514–320,520**，跨度百倍，**实测上界是初值的 2.6 倍** —— 也就是说 §6.4 那份「每天 8 次深度分析」的日配额，遇上重分析实际只够 3 次。**不悄悄改**：它是一次会影响教师可用额度的取值决定（要么按上界给，要么承认「8 次」指的是中位量级），留给 P5 或专门一次决定。
- **§5.4 的「run 级自动重试上限 1 次」从未落地**，实现是「一次都不自动重试」（2026-08-09 发现）。**尚未裁决是改文档还是补实现**，就地登记在 §5.4，两者都说得通。
- **`todo.updated` 与 `subagent.*` 两个事件仍无实测样本**（§5.2）。前者是因为实测中 agent 一次都没调 `write_todos`，后者是因为本期不开子 agent。契约位置已留好，但**前端的对应渲染分支没有真实数据可对照**，等到真正触发时可能要改。
  > **2026-08-13：`subagent.*` 这一半排进 P9 偿还。** [P6 决策 G6](../03plan/P6-decision.md) 要求「后端先补一条用**真实子图跑出来**的用例（不是构造的 chunk），前端做可展开折叠块」，且 `verify.sh` 里单列一条判据。**这是本次唯一一处事件契约第一次被真实数据填上的地方** —— `event/mapper.py` 的 `_map_path` 注释至今写着「实测 ns 全程为空，这条剥离逻辑没有真实子图样本验证过」。`todo.updated` 那一半仍然欠着。
