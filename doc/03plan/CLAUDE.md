### P6–P10：智能体配置与能力目录（2026-08-13 排期，计划文档待写）

需求是六条：上传 skill 并控制共享、自定义系统提示词、配置 MCP、为一次 run 挂子智能体；平台侧上传智能体、场景智能体。定案见 [P6-decision.md](./P6-decision.md)，切成五期的理由是**每期都要有一个能干净说出口的验收标准**：

| 期 | 内容 | 验收标准（一句话） |
|---|---|---|
| **P6** | 前端底座 + 提示词生效：API 层 + TanStack Query + SSE hook + HITL 审批 UI + Chat 真联调 | **配与不配自定义提示词，同一个问题的输出可见地不同** |
| **P7** | `agent` 表与版本序列 + CRUD + 三档可见性 + `reviewer` 角色 + 审核后台 | **组内共享的东西同组人看得见、别组看不见；未过审的进不了广场** |
| **P8** | skill 全链路：上传 → 七条校验 → 宿主机存储 → 开跑前全量对齐 → `SkillsMiddleware` | **挂与不挂同一个 skill，产物里看得出差别** |
| **P9** | 子智能体：一层、最多 5 个、共享沙箱、主模型 + **四处实测** | **嵌套事件带着真实 `path` 出现在前端；子智能体烧的 token 对得上账单** |
| **P10** | MCP：外网目录 + 勾选 + 超时熔断 + 外发标注 | **外网工具真被调用；连续失败 5 次真的自动停用** |

**P9 是最不确定的一期**，四处实测（嵌套事件的真实 `ns` 形状、子图 token 是否带得上来、嵌套中断能否被 `aget_state` 查到、子图 `recursion_limit` 是各自计数还是共享父图）任一处结果为否都会改变那一期的形状。**它单独成期正是因为这个。**

**验收脚本改形态**：不再一期一个，`p1.sh`–`p4.sh` 六个级联脚本整合成一个 `verify.sh` 默认全跑（保留 `SKIP_LLM` / `SKIP_HOSTILE` 等跳过开关）。**整合是一次重构，而被重构的东西是验收过的 —— 整合完必须原样重跑一遍确认没打穿**（[P3 §8.5](./P3-plan.md) 记着「本期改的接口打穿了三个历史验收脚本」，正是这类改动的形状）。

> **整合已于 2026-08-13 提前做掉**（在 P6 开工之前），落地为 [`deploy/test/verify.sh`](../../deploy/test/verify.sh)，22 条判据。
>
> **「必须原样重跑一遍」这条只完成了一半**：
>
> - ✅ **免费的 14 条已在真机上全过**（2026-08-14，XFS prjquota 正常挂载下）：P1③④⑤⑥、P2②③⑥、P3②③④⑤⑥、P4②⑦。
> - ⛔ **要花钱的 7 条跑不了**（P0①–⑤、P2①、P3①）：上游返回 `HTTP 402 Insufficient Balance`，**DeepSeek 账户余额不足**。这是外部原因，不是判据红 —— 按 [P4 §8.14](./P4-plan.md) 那条规矩，**记「未验」而不是「通过」，也不因为「外部原因」改判绿**。充值后重跑即可关闭。
> - ⛔ **要 root 的 1 条未跑**（P1①）：要 XFS 挂载 + 交互式 sudo。
>
> **在这 8 条补跑之前，不能说整合没打穿。** P5 欠的四条判据仍未补，见 [P5 §4](./P5-plan.md)。

## 路线基线

这张表原为总体架构 §11。拆分后移到实施计划索引，保留各期最初承诺与验收口径；具体定案和最终结果以上方各期计划为准。

| 阶段 | 内容 | 验证标准 |
|---|---|---|
| **P0** | FastAPI 内运行 DeepAgents、裸 Docker 沙箱、SSE 流式输出 | 用户能对话；Agent 能写 Python 读 CSV、计算并返回图表 |
| **P1** | gVisor、资源与磁盘配额、Sandbox Broker、生命周期管理 | 死循环、fork 炸弹、写满 workspace/tmp 均不影响宿主机 |
| **P2** | Redis Streams、Postgres Checkpointer、Run 与事件元数据 | `kill -9` Worker 后从 checkpoint 续跑，已完成步骤不重做 |
| **P3** | HITL、取消、多用户隔离、配额限流、工具幂等 | 审批走通；崩溃恢复不重复写；30 并发不崩溃、不串数据 |
| **P4** | ~~OpenTelemetry、MinIO 产物、成本看板~~ | ~~能定位单个 Run 的完整 Trace 与 Token 花费~~ → **三项交付物在 2026-08-12/13 全部撤除**。「定位」与「花费」都改到外部的 Langfuse 上看；平台内留下的是 JSON 日志（排障）与 `runs.tokens_*`（配额闸门的判据）|

**P5 不在这张基线表里** —— 它是 P4 之后为支撑前端补的一层接口，目标由[运行时设计 §5.7](../01design/05runtime-design.md) 的接口契约表给出，不另立验证标准。

验收脚本是 [`deploy/test/verify.sh`](../../deploy/test/verify.sh) **一个文件，22 条判据**。判据编号沿用各期计划 §4 的编号（`P1③`、`P2①`…），每条该看到什么、失败时看哪里仍写在各期计划的 §4 与 §8。

> **2026-08-13 由七个脚本合并而来**（`p1.sh` / `p2.sh` / `p3.sh` / `p4.sh` / `acceptance.sh` / `hostile.sh` / `session.sh`）。原来是逐级转调，`p4.sh` 调 `p3.sh` 调 `p2.sh` 调 `p1.sh` 调另外两个，跑 `p4.sh` 等于把五期跑一遍。**结果表里因此断了六个号**：P1②⑤、P2④⑤、P3⑦、P4⑧ 原本只是「去跑另一个脚本」，不验任何东西 —— 删掉的是转调，它们指向的判据一条不少。合并的另外两个理由（四份各不相同的前置检查、每多一级转调就多一次「未验」的翻译）与一并修掉的六处漂移，写在脚本文件头。
>
> **别与别的东西抢这套栈** —— 它会 `kill -9` broker 与 worker、重启三个进程、停 worker、压限流。同时有人在用的结果是双方都红，且红在互不相干的地方（[P4 §8.10.1](./P4-plan.md) 实测踩过）。

> **每份计划的固定骨架**：§1 边界（做什么／不做什么，不做的每条写明由哪期偿还）→ §2 与上游文档不一致处的本期定案 → §3 环境前提 → §4 验收标准（一条命令能跑完）→ §5 任务分解（每步独立可验，未过不进下一步）→ §6 回归关系 → §7 待决事项。
>
> **§1.3 的「明确不做」是这套文档最该认真读的一节** —— 它是技术债的登记簿。每条都带偿还期次，翻一遍就知道现在的平台差在哪，而不必去猜。
