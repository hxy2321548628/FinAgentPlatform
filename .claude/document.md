# 文档撰写规范

---

## 一、格式

- **统一 Markdown**：所有文档用 `.md`，标题层级清晰，命令 / 代码用代码块包裹。
- **图用 Mermaid**：流程 / 时序 / 架构 / 状态图一律用 mermaid 代码块，不用截图（不可 diff、易失效）。
- **单数命名**：文件 / 目录名用单数。

---

## 二、单一文件源（Single Source of Truth）

- **一处定义**：同一信息只在一个主文档完整描述。
- **跨文档用链接**：他处引用给相对链接，不复制正文。复制 = 改一处漏三处。
- **就近引用代码**：指向实现时用仓库相对路径 / 行号锚点，让描述随代码可追。

---

## 三、职责单一

- **一档一责**：每个文档只回答一个核心问题，标题即职责。
- **索引先行**：每个文档目录用 `CLAUDE.md` 维护索引（文档名 → 职责 → 回答什么问题）。

---

## 四、可核对

- **绝对日期**：写具体日期（`2026-07-06`），不写"下周 / 三天后"。
- **决策留痕**：关键取舍写清"选了什么、为什么、放弃了哪个替代方案"。
- **随代码同步**：设计与实现分叉时，改文档或改代码，不留过期描述。
