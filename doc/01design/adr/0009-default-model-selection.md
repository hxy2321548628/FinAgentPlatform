## 背景

平台需要选择驱动智能体的 LLM。金融分析是典型的多步推理任务：读数据 → 判断该用什么方法 → 写代码 → 看结果 → 修正 → 得出结论。

## 决策

- **主模型**：`deepseek-v4-pro`，开启 thinking，`effort` 先设 `high`，再按实际路由压测调整
- **辅助调用**（意图分类等轻量任务）：下沉到 `deepseek-v4-flush` 以控制成本
- **模型接入层做成可替换**：若后续因保密要求转为内网私有化部署，只替换该层，不影响上层设计

## 理由

金融分析这类**多步推理**任务，提高 effort 的收益比换用更大的模型更明显 —— 多步任务中每一步的判断质量会沿链路累积，推理深度的边际收益高。

辅助调用（意图分类、标题生成这类）不需要推理深度，用主模型是纯浪费，下沉到轻量模型可显著降低成本。这与 §3.1 中「成本可控」被列为 P1 质量属性一致。

**接入层可替换**这一条是对冲风险的：主模型走公有云 API，而 §10.1 的出网通路和 §2.4 的数据合规都还没有确认结论。如果任一条走不通，需要能低成本切换到内网私有化部署的模型，不能让整个上层架构陪葬。

## 后果

**正面**：
- 推理深度匹配任务特性
- 辅助调用下沉可观地降低成本
- 接入层抽象使模型切换不波及上层

**代价**：
- **依赖公有云 API，受 §10.1 出网通路阻塞**。这不是选型问题而是平台能否运行的硬前提
- **教师数据会作为 prompt 的一部分离开内网**，受 §2.4 合规约束。若合规不允许，本决策整体不成立
- 受 LLM 服务商的 rate limit 约束，并发高峰时可能集中报错，worker 侧需要退避重试与降级策略（尚未设计，见 §10.2 风险登记）
- 成本随使用量线性增长，必须配合 §6.4 的配额机制

- 出网通路或合规审查任一不通过 → **必须重新决策**，转内网私有化部署
