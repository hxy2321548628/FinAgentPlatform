# 验收指南索引

每期一个目录，回答**「这一期的验收怎么一步步跑完」**。验收标准本身（为什么是这几条）在对应的[实施计划](../03plan/)里，本目录不复制。

| 文档 | 职责 | 回答什么问题 |
|---|---|---|
| [P0/P0验收postman指南.md](./P0/P0验收postman指南.md) | P0 四条的手工操作步骤 | 怎么用 Postman 把「事件流完整 / agent 自写代码 / 断线重连 / 产物取回」四条走一遍 |
| [P1/P1验收指南.md](./P1/P1验收指南.md) | P1 六条的脚本化操作步骤 | 怎么用 `deploy/test/p1.sh` 一条命令跑完六条，每条该看到什么、失败时看哪里 |

配套数据与脚本：

- `P0/holdings.csv` —— 验收专用样例数据（6 只股票 × 7 个月，含一处故意留空的收盘价），不是业务数据。`acceptance.sh` 也用它。
- 三个脚本在 [`deploy/test/`](../../deploy/test/)：`p1.sh` 是 P1 的总入口，转调 `hostile.sh`（破坏性四条）与 `acceptance.sh`（P0 回归四条）。

> **P0 手工、P1 脚本，不是风格摇摆**：P0 验的是「agent 好不好用」，判据里有「图看着对不对」这类只能靠人眼的东西；P1 验的是「限制是否生效」，六条里有四条要 kill 进程、改配置、写满磁盘，手工做既慢又容易漏。
