# ADR-0012：内网走 HTTP，不启用 TLS

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-07-31 |
| 决策人 | hxy |
| 主文档关联 | §4.4 部署架构、§7.4 数据安全 |

## 背景

§4.4 确认平台部署在校园内网，**用内网 IP 直接访问，没有域名**。没有域名就签不了受信证书。

## 决策

**不启用 TLS**，浏览器到 Nginx 走明文 HTTP。

## 理由

可选项只有三个：

- **走 HTTP** —— 内网部署、实名用户、无敏感数据（§2.4），风险可接受。SSE 不要求 secure context，功能上无影响
- **自签证书** —— 浏览器每次弹红色警告。除非把根证书推送到全院每台机器，否则教师体验很差；更糟的是**它会训练用户忽略证书警告**，这本身是个负面的安全习惯
- **申请域名 + 校内 CA** —— 最正确的做法，但需要走流程，与本期「先跑通」的定位（§1.1）不匹配

在威胁模型（§7.1）中，外部定向攻击的可能性被判为低，而自签证书的体验代价是确定的。

## 被放弃的备选

| 备选 | 放弃理由 |
|---|---|
| **自签证书** | 浏览器持续告警，除非全院推根证书；且会训练用户忽略证书警告 |
| **申请域名 + 校内 CA 证书** | 需走流程，本期不做。**这是将来需要 TLS 时的首选路径，不要退回自签** |

## 后果

**正面**：
- 部署简单，无证书管理与续期负担
- 排障可直接抓包、`curl`

**代价**：
- **Session Cookie 无法设置 `Secure` 标志**（[ADR-0011](./0011-cookie-session-not-oauth2.md)），凭据在内网链路上明文，同网段抓包可窃取会话
- 上传的数据文件与分析结果在链路上明文传输
- **所有依赖 secure context 的浏览器 API 不可用**：剪贴板 API、通知、Service Worker、`getUserMedia` 等。若将来前端需要其中任何一个，必须先解决 TLS

## 重新评估的触发条件

- 前端需要用到依赖 secure context 的浏览器 API
- 平台开放到内网之外
- 开始承载敏感数据（§2.4 的合规结论发生变化）

> 触发时应**申请域名 + 校内 CA 证书**，而不是退回自签。
