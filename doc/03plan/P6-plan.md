## 1. 边界

### 1.1 这一期要证明的那一件事

`threads.agent_config` 这个 JSONB 从 2026-08-08 的 `0003_user_thread` 就在库里，横跨 P3、P4、P5 三期：`PATCH` 写得进、`GET` 读得出、测试覆盖着、`make all` 全绿 —— **而装配层从来没有读过它一次**。

```python
# app/agent/factory.py:184，从 P0 至今没变过
create_deep_agent(model=..., backend=backend, system_prompt=SYSTEM_PROMPT, ...)
```

`SYSTEM_PROMPT` 是 `agent/prompt.py` 里的模块级常量。**这个字段对 agent 行为的影响是零，而三期里没有任何一道门禁发现过这件事。**

本期要做的就是让它第一次真的起作用，并且**给这件事留下一条能跑的判据** —— [P6 决策 §11](./P6-decision.md) 的总原则正是从这里来的：

> 一条配置的验收标准，永远是「配与不配，行为可见地不同」，不是「接口返回 200」。

### 1.4 本期接受的风险与技术债

1. **前端没有自动化验收，这是本期最大的一笔债。** §4 的三条脚本判据全部验后端 —— 前端接没接上、审批 UI 点不点得动、SSE 断线重连在浏览器里成不成立，脚本一条都验不到。**本期靠一次人工走查兜底**（清单在 §4.4，结果记进 §8）。

   > **风险的形状要说清**：这正是本期反复警惕的那种失效 —— 前端可以「渲染出来了、不报错」而数据全是假的。人工走查是能做的最低限度，不是充分的。**若 P7 前端工作量继续涨，引入 playwright 的时机就到了。**

2. **P6 当时的 `agent_config` schema 只认识提示词**（§1.3 第 1 条），因此 `{"skills": [...]}` 会被 `extra="forbid"` 当场 422，而不是写入后静默不生效。

   > **P8 已偿还**：`skills` 现在是正式字段；守 `extra="forbid"` 的 `test_an_unknown_field_is_rejected` 改用 `{"not_supported": true}`，没有删除或放宽未知字段闸门。

3. **TanStack Query 的改动面是全量而不是增量**（J1 已记）。本期只重写主链路那几个页面，**其余页面仍是 mock + 手写状态** —— 两种范式会在代码库里并存到 P10。

4. **HITL 审批 UI 只覆盖 `delete` 一个工具**。后端 `INTERRUPT_ON` 现在只拦它；将来加 `execute` 的条件拦截时（`factory.py` 那段注释写着的条件），审批 UI 要能渲染任意工具的 args —— 本期按「通用渲染」写，但只在 `delete` 上验过。

## 3. 环境前提

除[根 CLAUDE.md](../../CLAUDE.md) 的常规前提（XFS 挂载、broker force-recreate、六个服务起着）外，本期新增三条：

**① 前端 dev server 与 API 不同源，必须走 vite proxy**

```
浏览器 → localhost:5173（vite）──/api/*──→ localhost:80（nginx）→ api
```

不配代理的话有两条死路，**两条的症状都不指向真因**：

| 走法 | 症状 | 真因 |
|---|---|---|
| 前端请求 `/api/...` | 404，返回的是 vite 的 index.html | 打到了 dev server 自己身上 |
| 前端请求 `http://localhost/api/...` | 浏览器控制台的 CORS 报错，请求根本没发出去 | 跨 origin，而后端**没有配 CORS**（内网同源部署本来不需要） |

**代理是唯一的路**：它让浏览器看到的是同源请求，Cookie（`SameSite=Lax`、无 `Secure`）照常带上。生产部署走 nginx 同源，不受影响。

```ts
// web/vite.config.ts
server: { proxy: { '/api': { target: 'http://127.0.0.1:80', changeOrigin: false } } }
```

> **`changeOrigin` 保持 `false`**：置 true 会重写 `Host` 头，而 nginx 那侧按 Host 分流。这一条现在无所谓，将来加虚拟主机时会变成一个难查的 502。

**② 要一个能登录的账号。** `.env` 的 `ADMIN_NAME` / `ADMIN_PASSWORD` 只在**空库**时建一次首个管理员。库非空且忘了口令时，照 `verify.sh` 的 `make_user` 那段进 api 容器算哈希、进 postgres 插行。

**③ SSE 经代理不能被缓冲。** vite 的 proxy 默认不缓冲，nginx 那侧 P1⑤ 已经验过（心跳能穿过 60s 空闲上限）。**但两层代理串起来是本期第一次** —— 若事件流在浏览器里成批到达而不是逐条，先查这一层。


| 判据 | 内容 | 成本 |
|---|---|---|
| **P6①** | **配与不配自定义提示词，同一个问题的输出可见地不同** | 两次真实分析 |

### 4.2 `P6①` 怎么写才算真的验到了

**这是本期唯一一条能证明「这件事成了」的判据，因此它的形状要先说清楚。**

```
会话 A：不配 agent_config          ──提问 Q──→ 回答不以「喵」开头
会话 B：配 {"system_prompt": "…每一句都以「喵」开头…"} ──提问 Q（同一句）──→ 回答以「喵」开头
```

**四条要求，缺一条这条判据就会假绿**：

1. **两个会话，不是同一个会话问两次。** 同一个会话的第二次提问带着 checkpoint 里的历史，回答会受上一轮影响 —— 那时分不清是配置起作用还是上文起作用。
2. **双向断言。** 只断言 B 带「喵」是不够的：**A 也带喵**说明串了（比如配置漏进了全局），**两个都不带**说明配置压根没生效。两种都要判出来。
3. **指令要显眼且与分析内容无关。** 「以喵开头」这类格式指令，判起来是字符串比对，不需要理解语义 —— 判据不能依赖对回答质量的主观判断。
4. **问题要便宜。** 不用 P0 那种完整分析（30 万 token）。一个不需要写代码的问题即可，但**仍要跑到 `succeeded`** —— 半路失败的 run 证明不了提示词生效。

> **这一条同时把 H2 验掉了。** [H2](./P6-decision.md) 核实了源码（system message 每次模型请求动态 prepend、不进 checkpoint），结论是「改配置下一次 run 就生效」。**核实源码不等于验过行为** —— 这是[「先验证验证代码」](../../CLAUDE.md)的直接应用，H2 自己也写着要在验收里带一条确认。

### 4.3 `P6②` 与 `P6③` 的形状

**`P6②`**：直接调拼接函数，不跑模型。

给一个会跟平台契约打架的用户提示词（`把图保存到当前目录`，[E4](./P6-decision.md) 说这是最自然的写法之一），断言拼出来的 prompt 满足：

- 用户那句在里面（①角色段确实被替换了）；
- ②环境契约的五条**全部还在**（用户覆盖不掉）；
- **②整段落在用户那句之后** —— [E1](./P6-decision.md) 写着「顺序是这条定案里唯一真正起作用的机制，分段只是让它更整齐」。

**`P6③`**：验快照不随后续改动而变。

1. 建会话 → `PATCH agent_config = A` → 提交 run（worker 停着，run 停在 queued）→ 库里 `runs.agent_config == A`
2. `PATCH agent_config = B` → **那条老 run 的快照仍是 A**
3. 再提交一条 → 新 run 的快照是 B

### 4.4 前端的人工走查清单（没有自动化，见 §1.4）

**每一条都要在浏览器里真点一遍**，结果逐条记进 §8。清单按主链路的顺序排：

| # | 动作 | 该看到什么 | 最可能的静默失效 |
|---|---|---|---|
| 1 | 用真账号登录 | 跳进工作台，`GET /auth/me` 拿到真名字与角色 | 仍走 `demoAuth`，随便输什么都进得去 |
| 2 | 会话列表 | 是库里的真会话，翻页用游标 | 列表是 `THREAD_TITLES` 那三条 mock |
| 3 | 新建会话 → 提问 | `POST /threads` 201、`POST /runs` 202 | 提问按钮什么都不发 |
| 4 | 事件流 | token 逐字出现，工具调用与结果成对出现 | 渲染的是 `MULTI_AGENT_MESSAGES` 那段 mock |
| 5 | 运行中断网再恢复 | 已有 UI 保留；重连请求用内存游标发 `Last-Event-ID`，断线期事件**不重不漏**地补齐 | 不带游标从头重放，已有 UI 出现重复内容 |
| 6 | 整页刷新 | 不复用上一页的游标或 UI；从头重放到空 reducer，重建出一份完整对话 | 只持久化游标，导致游标之前的对话丢失 |

### 4.5 门禁

`make all` 本期起同时跑两侧，**未全绿不得提交**：

```
Python：ruff format --check · ruff check · mypy · pytest
web：   oxlint · tsc -b · vitest
```

**前端单测的范围**（技术宪法第一条要求核心逻辑 80%）：

| 测什么 | 为什么是它 |
|---|---|

## 5. 任务分解

**每步独立可验，未过不进下一步。** 后端（步骤一～四）与前端（步骤五～八）之间只有一处依赖：前端的配置面板要等步骤四的接口定型。
