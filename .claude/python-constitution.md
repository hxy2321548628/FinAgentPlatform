# Python-技术宪法（不可动摇）

以下原则适用于所有任务，优先级高于其他指令。
根本遵循 **PEP 20（The Zen of Python）**：显式优于隐式，简单优于复杂，可读性至关重要，错误不应静默传递。

---

## 第一条：测试先行铁律（Test-First）

- **TDD 流程**：任何新功能 → 先写测试（Red）→ 再写实现（Green）→ 最后重构（Refactor）。
- **覆盖率下限**：核心逻辑测试覆盖率不低于 80%（覆盖率工具验证，如 `pytest --cov`）。
- **禁止空测试**：禁止没有断言的测试，禁止只为提高覆盖率而写的测试。
- **测试即文档**：测试函数名清晰描述"在什么情况下，期望什么结果"（`test_<场景>_<预期>`），并遵循项目统一的测试文件命名约定。
- **异步同源**：异步代码用异步测试覆盖（`async def test_*`），不得用 `asyncio.run` 包一层绕过真实执行路径。

---

## 第二条：明确性原则（Explicit over Implicit）

- **异常不可吞掉**：禁止裸 `except:` 与 `except Exception: pass`。异常要么处理、要么显式向上抛出、要么带上下文记录后重抛；捕获时指明具体异常类型。
- **禁止全局可变状态**：禁止模块级可变全局变量与可变单例；杜绝可变默认参数（`def f(x=[])` 一律改用 `x=None` 再在函数内初始化）。
- **依赖倒置**：业务逻辑依赖抽象（`Protocol` / ABC），不依赖具体实现；跨层调用只认接口，不认具体类。
- **依赖显式注入**：外部依赖（client、session、配置）通过参数或构造函数传入，禁止在函数内部就地初始化。
- **类型显式**：公开函数签名必须带类型注解，禁止用 `Any` 兜底（细则见代码风格指南）。
- **参数封装**：函数参数超过 4 个时，用 `dataclass` / pydantic 模型 / keyword-only 参数封装，并为每个字段加说明。
- **禁止硬编码**：关键参数、魔法数字置于文件 / 模块顶部常量，不散落在函数体内。
- **引入第三方库**: 使用`uv add`, 不使用`uv pip install`, 安装包应该显示记录依赖再`pyproject.toml`文件中

---

## 第三条：单一职责原则（Single Responsibility）

- **模块的职责**：每个模块 / 包只做一件事，模块名即职责描述（如 `auth`、`payment`、`notification`）。
- **函数长度**：函数超过 50 行时，必须拆分。长函数是职责不单一的信号。
- **禁止"上帝函数"**：一个函数不能既做 IO、又做业务计算、又做格式化输出。
- **接口粒度**：`Protocol` / ABC 只包含调用方真正需要的方法，不暴露多余方法。

---

## 第四条：自动化质量门禁（Automated Quality Gate）

- **工具即裁判**：格式化、lint、类型检查由工具统一执行（如 ruff / black / mypy），代码风格不靠人争论。
- **本地门禁（强制）**：本地用 `make` 一条命令跑完格式化 / lint / 类型 / 测试；未全绿不得提交。
- **远端门禁（有远程仓库即强制）**：一旦存在远程仓库，必须配置 CI（如 GitHub Actions）跑与本地**同一套** `make` 检查；纯本地仓库可暂不配。检查项只定义一处（Makefile），CI 只负责调用，不得复制命令。
- **拦截点不可缺席**：走 PR 协作时开启分支保护，未过不得合并；直推主干时没有 PR 可拦，事前拦截由 `pre-push` hook 承担，CI 退居 push 之后的第二层网。两种形态都必须有一个**事前**拦截点，不得只剩事后报警。
- **零告警入库**：新增代码不引入新的 lint / 类型告警；不用 `# noqa` / `# type: ignore` 掩盖问题，除非同行注释说明理由。
- **可复现环境**：依赖锁定、可一键重建（lock 文件 + 虚拟环境），杜绝"在我机器上能跑"。
