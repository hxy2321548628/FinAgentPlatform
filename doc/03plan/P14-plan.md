## 2. 开工前实测与本期定案

**五处已跑完**（2026-08-19，全部免费、不调真实模型）。**一处照出平台既有的一个 bug，它决定了步骤一。**

### 2.1 `respond` 不带 `message` 时，恢复那一刻 `KeyError` —— **本期第一个要修的**

探针（`app.run.decision` + `HumanInTheLoopMiddleware._process_decision` 直调）：

```
平台侧校验通过，转出的形状： [{'type': 'respond'}]
恢复时抛： KeyError 'message'
带 message 时： ToolMessage(content='按等权重', name='ask_user_question', status='success')
```

[`decision.py`](../../src/app/run/decision.py) 的 `check()` 只管 `edit` 缺不缺 `edited_action`，`respond` 缺 `message` 一路放行；`to_resume()` 于是转出一个没有 `message` 键的字典，而库里那支直接 `decision["message"]`。

**为什么至今没暴露**：现有的两个可中断工具（`delete`、`execute`）都允许 `approve`，教师不会去选 `respond`；而前端 [`decisions.ts`](../../web/src/workspace/decisions.ts) 自己强制了「回复必须填理由」。**本期的 `ask_user_question` 是第一个只允许 `respond` 的工具**，任何脚本客户端（含[评估 runner](../../script/eval/client.py)，它的 `_decision_for` 只发 `{"index", "type"}`）第一次调用就会踩到。

⚠️ **它失败的样子最坏**：教师点了「回复」→ 平台 202 接受 → 重投任务 → worker 在恢复时炸 → run 记成 `INTERNAL`，**而错误信息一个字都不指向「少了一句话」**。这与 [P12 §7](./P12-plan.md)「红得像装包失败」是同一个形态。

### 2.2 `write_todos` 的 state 更新真的流得到 `updates`，形状与压缩痕迹同型

假模型探针（`create_deep_agent` + `TodoListMiddleware`，`StateBackend`，`InMemorySaver`）：

```
[updates] ns=() node=model  keys=['messages']
[updates] ns=() node=tools  keys=['todos', 'messages']
   todos 载荷 = [{'content': '读取数据', 'status': 'in_progress'}, {'content': '算波动率', 'status': 'pending'}]
   msg: ToolMessage "Updated todo list to [...]"
state 里的 todos = [{'content': '读取数据', ...}, ...]
```

三条结论，各自决定一处落点：

- **事件映射接在 mapper，不需要自定义中间件** —— `tools` 节点的 update 里多一个 `todos` 键，与 [`_map_compaction`](../../src/app/event/mapper.py) 读 `_summarization_event` 是同一个形状；
- **`todos` 进了 state 且 `aget_state` 读得回来** —— A7 的进度节可以读 `request.state`，不必自己从消息里重建；
- ⚠️ **同一次调用还会照常产出一条 `tool_result` 事件，正文是英文的 `Updated todo list to [...]`** —— 不管它的话，教师会同时看到一张英文工具卡片和一张中文清单，**同一件事显示两遍**。

> **探针本身踩过一跤，记下来省得下次再踩**：`GenericFakeChatModel` 流式那支会把 `tool_calls` 丢掉（症状是 `ValueError: No generations found in stream`，看着像消息构造错了）。要验工具调用链路必须 `disable_streaming=True`，走 `_generate` 那支。

### 2.3 上游那份能力自带 5243 字符的英文提示词

| 项 | 字符数 |
|---|---|
| `WRITE_TODOS_SYSTEM_PROMPT`（注入系统提示词） | 1370 |
| `WRITE_TODOS_TOOL_DESCRIPTION`（工具描述，进工具 schema） | 3873 |
| **平台自己的系统提示词全文**（`compose_prompt()`） | **644** |

**它是平台自己那份的八倍。** 两件事因此要写清楚：

- **缓存上是安全的**：`TodoListMiddleware.wrap_model_call` 追加的是**静态** prose，前缀仍逐字节稳定 —— [P13 的 `prefix_test.py`](../../src/test/agent/prefix_test.py) 那条规则不会被打破（步骤四要跑一遍确认）；
- **但 P13 量的成本基线不再可比**：每次分析的第一轮要为这块多付一次未命中，之后靠服务端前缀缓存吃掉。**这正是本期收尾要重跑一轮评估集的理由**（步骤十），不是为了证明本期变好了，是为了给 P15 一条能用的基线。

⚠️ **英文提示词还有第二个代价**：条目由模型写，而提示词全英文会诱导它写英文条目 —— **教师看见的清单可能是英文的**，那与项目「面向用户的文字一律中文」直接冲突。构造器接受 `system_prompt` 与 `tool_description` 两个参数，本期换成中文版并在里面点明「条目用中文写」。

### 2.4 `respond` 的语义正是「ask user」型工具，不必自己造挂起机制

库里 `RespondDecision` 的 docstring 原话：*Used for "ask user" style tools whose real implementation is the human's response. The tool is not executed; instead, a synthetic ToolMessage with status="success" and the provided message is returned to the model.*

§2.1 那次探针的第三行已经验到：带 `message` 时**工具不执行**，教师的话作为 `status="success"` 的 `ToolMessage` 回给模型。**[B2](./P13-decision.md) 说的「复用一条已验收的路」成立** —— 本期新增的只有工具本身、前端渲染、和一条决策校验。

### 2.5 两个新工具名不在撞名保留清单里

[`mcp.py`](../../src/app/agent/mcp.py) 的 `RESERVED_TOOL_NAME` 硬编码九个名字（八个文件工具 + `task`），`write_todos` 与 `ask_user_question` **都不在**。

⚠️ **顶掉 `ask_user_question` 比顶掉 `read_file` 更坏。** [P10 §2](./P10-plan.md) 实测过外部工具会**静默顶掉**内置工具；而这个工具接的是教师的嘴 —— 被顶掉之后，agent 的提问和教师的回答会一起发去校外那台服务器，**而它看着像内置工具，[F13](./P6-decision.md) 那条外发标注不会标它**。

### 2.6 四处拍板（2026-08-19）

| # | 项 | 定案 | 接受的代价 |
|---|---|---|---|
| 1 | 子图装不装任务清单 | **不装，只主图** | 子智能体干的活教师看不到进度。**与 `INTERRUPT_ON`「主图子图必须同一份」那条规矩相反是有意的**：那条管的是安全闸，漏一处就漏一条绕过路径；清单是展示，多一张只会与主清单互相覆盖，前端还要回答「哪张是当前的」。[`TailContextMiddleware`](../../src/app/agent/tail.py) 也只装主图，有先例 |
| 2 | 子图装不装提问工具 | **装，两处都装** | 与上一条相反，理由同样来自 `INTERRUPT_ON`：子智能体卡住却问不出来，只会瞎猜着往下做。[P9⑤](./P9-plan.md) 已验过嵌套中断两半都通，这是走已验收的路 |
| 3 | 进度节报什么 | **只报「已完成 x/y + 正在做的那条」，不复述整张清单** | 模型要看细节得回翻历史里的 `ToolMessage`。复述整张的代价是每轮重复计费同一份内容，而清单原文本来就在轨迹里 —— 书 2.6.5 的形态是**读数 + 策略**，不是把数据再抄一遍 |
| 4 | 提问型与审批型中断怎么分流 | **不加字段，前端按 `tool_name` 分流** | 工具名成了前后端共用的隐式常量，两边各一处、注释互指（与 `tail.py` 的 `INSTALL_MARKER` 同一形态）。**不加 `kind` 字段是 [P11 §2.4](./P11-plan.md) 的教训**：工具名就是那个客观事实，加字段等于造第二个真相源 |

### 2.7 开工前必测（三处，结果为否会改变步骤）

形状与 [P9 的四处实测](./P9-plan.md)相同。**它们都要真实模型费用，因此排在步骤二与步骤四之后、当场就测，不单开一步。**

1. **模型到底用不用这两个工具。** 清单那份提示词自己写着「少于 3 步就别用」，而金融分析多是 5–10 步 —— 但这要真跑才知道。⚠️ **一次都不调用，这个功能对教师就不存在**，那时要改的是工具描述与提示词界定句，不是前端。**判据记「未验」不记「过」。**
2. **反过来，提问会不会滥用。** agent 每道题都停下来问一次，教师就被打断到不想用。要量一批题里提问的次数分布 —— 这个数决定工具描述里那句「什么时候才该问」写得多硬。
3. **一次中断里同时有审批和提问会怎样。** `check()` 要求决策覆盖**全部** index（[P13 步骤四](./P13-plan.md)踩过：只批第一个是 422，而那个红看着像 agent 没做好），混合中断时前端要能对每个 action 分别选决策类型。

## 5. 任务分解

**顺序有两条不能颠倒**：`respond` 的洞要在任何人走它之前补上（步骤一）；工具装上之后立刻做 §2.7 的实测，**因为「模型根本不用」会推翻后面三步的形状**。

| # | 做什么 | 验 |
|---|---|---|
| **一** | **补 `respond` 缺 `message` 那个洞**：`decision.check()` 要求 `respond` 带非空 `message`；[评估 runner](../../script/eval/client.py) 的 `_decision_for` 跟着配一句话 | 单测正反两向；**P14②** |
| **二** | `ask_user_question` 工具 + `INTERRUPT_ON` 只允许 `respond`（主图与子图两处），工具名进 `RESERVED_TOOL_NAME` | 装配单测；假模型探针走一遍中断；`mcp_test` 那条撞名用例 |
| **三** | **§2.7 第 1、2 条当场实测**（真跑两三道题）：模型到底问不问、问得多不多 | 结论写进实施记录；**为否则回到步骤二改工具描述** |
| **四** | 装 `TodoListMiddleware`（只主图），换成中文 `system_prompt` 与 `tool_description`（点明条目用中文） | 装配单测；**`prefix_test.py` 三条必须仍绿**（§2.3：静态注入不该动前缀） |

## 7. 待决事项

1. **教师一直不回答会怎样 —— 「等审批」与「等回答」是不是同一套超时口径。** 这条是 [B2](./P13-decision.md) 点名要本计划回答的。
   **定案：同一套。** `waiting_approval` 挂着既不占队列消息也不占沙箱，24 小时之后由 cron 转 `cancelled`；一人最多挂 5 个。
   **接受的代价有两条，都要写下来**：① 一个等回答的 run 会占掉那 5 个审批名额，教师同时开几个会话时可能被 `PENDING_LIMIT` 挡住，而那时的报错说的是「待审批太多」，不提「其中三个是 agent 在问你话」；② 24 小时对提问多半太长 —— 审批是「教师下班后才看到」，提问是「教师就在屏幕前」。
   **重估条件**：上线后量一批真实提问的回答时延，若绝大多数在几分钟内，就把提问的超时单独调短。**现在不预设那个数**，因为手里一个样本都没有。
2. **`todos` 按 thread 持久，第二问会看到上一问的残留清单。** §2.2 的探针已证明它进了 checkpoint。中间件本身不把清单注进提示词（只有静态 prose），所以模型看到的仍是历史里的 `ToolMessage` —— **但 A7 的进度节读的是 state，它会理直气壮地报出一张上一问的清单**。
   **暂定处置**：进度节只在「最近一条 user message 之后出现过 `write_todos`」时才开口，与 tail「没话说就闭嘴」一致。**要在步骤八实测确认**：模型第二问时是自己覆盖清单，还是接着上一张勾 —— 两种行为对应的处置不同，现在猜不出来。
3. **`todo.updated` 的 `path`。** 定案只给主图装清单（§2.6 第 1 条），因此事件的 `path` 恒为空元组。**若将来子图也要清单，前端必须先回答「哪张是当前的」** —— 这一条留在这里，是为了那天有人翻到它。
