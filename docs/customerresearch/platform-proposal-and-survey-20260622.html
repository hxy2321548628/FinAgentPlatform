建设一个金融领域垂直 AI 平台，将大模型能力与学院数据资源打通，让教师和学生低门槛调用 AI，将科研/教学重复性工作自动化，并建立可沉淀的 AI 工具资产库。

目标三：资产沉淀

效果稿描述的五层平台架构
我们的理解——每一层的定位与依赖关系
⚠️
效果稿以 L0→L4 层级代号命名，这是架构视角，并非用户认知视角。实际产品导航应以使用者任务为中心命名，详见第四节。
L0

数据底座（Data Assets）

金融市场数据（公告、财报、交互问答）+ 科研数据（论文、项目书、复现数据包）。这是上层检索和分析能力的原材料，必须先就绪，才能做有意义的 AI 问答。

L1

公共服务（Infrastructure Services）

本地 LLM 接入 + 语义检索/向量化 + 文档解析 + 统一 API 网关 + 任务调度引擎 + 日志计量。平台内所有智能体共用这些底层能力，不需要每个 Agent 各自重复实现。

L2

智能体层（Agent Plaza & Builder）

智能体广场（浏览/运行已发布工具）+ 4 步创建向导（基本信息→绑定能力→配置策略→测试发布）。核心是让教师自助搭建工具，让学生（使用者）低门槛运行。

L3

编排层（Task Chain Workbench）

可视化 DAG 多智能体编排：串行、并行、条件分支、扇出聚合。这是效果稿中技术复杂度最高的模块，实现工期约为 L2 的 2-3 倍，需要明确是否一期必须。

L4

场景库（Scene Library）

预制模板：企业风险分析 / 论文分析 / 立项参考。使用者填写参数后一键运行，无需理解背后 Agent 逻辑。对学生友好，入门门槛最低。

🔍
效果稿中我们发现的 5 处待补全内容
需要确认方向，避免开发过程中走弯路
① 纯教师视角，遗漏了学生

效果稿登录用户为"陈老师·教师"，所有操作流程均从创建/管理出发。学生如何注册？能看什么？能做什么？完全缺失。

② 导航是架构代号而非用户语言

"L0 数据底座" "L2 智能体部件"等命名是内部开发视角，真实用户应看到"数据资产""AI 广场""场景库"等功能化表达。

③ L0 数据来源完全未说明

Wind 数据、财报、论文从哪来？是已有系统对接、手动上传还是爬虫？这决定了 L0 的工作量是"配置接口"还是"从零建设数据管道"。

④ L3 任务链是否一期必要未明确

可视化 DAG 编排器是平台最高复杂度模块，如果可以延后，一期工期可缩短约 40%，优先保证 L2/L4 高质量落地。

⑤ 场景库的维护权责不清晰

预制场景由谁维护？教师能否自建新场景模板？学生能否修改参数再次运行？这影响场景库的权限和数据模型设计。

影响发布工作流和管理员界面的设计。
